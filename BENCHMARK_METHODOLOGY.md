# PatchProof Benchmark Methodology

## 1. Objective

PatchProof is a prototype benchmark for evaluating AI-generated software patches against explicit contract tests. The current controlled experiment checks whether the evaluation harness accepts reference implementations and detects selected, deliberately introduced defects.

## 2. Benchmark tasks

- **PP-001 — Validate percentage discounts:** checks non-negative prices, valid discount percentages, expected calculations, and a calculation-order edge case.
- **PP-002 — Rounding contract:** checks calculation results, two-decimal rounding behavior, and invalid input handling.
- **PP-003 — Filter prices by maximum:** checks inclusive maximum-price filtering, original order preservation, duplicate handling, and boundary cases.

PP-001 contains 9 tests, PP-002 contains 12 tests, and PP-003 contains 8 tests.

## 3. Controlled candidates

Six candidate implementations are included in the current experiment:

1. `reference`: positive control expected to pass all task contracts.
2. `missing_discount_validation`: omits discount-range validation.
3. `missing_price_validation`: omits negative-price validation.
4. `wrong_rounding_precision`: rounds to one decimal place.
5. `rounds_before_discount`: rounds the original price before applying the discount.
6. `excludes_prices_at_limit`: incorrectly excludes prices equal to the maximum.

These candidates are hand-written controls. They are not substitutes for patches generated by AI models.

## 4. Procedure

Run the experiment with:

`python .\run_benchmark_experiment.py`

The experiment evaluates each configured candidate against PP-001, PP-002, and PP-003. The current configuration produces 18 candidate-task evaluations per run.

The script writes the experiment report to `results/benchmark_experiment.json`. The report records candidate/task outcomes and test counts.

## 5. Observed results

In the latest recorded run:

- The reference candidate passed all three tasks.
- The four discount and rounding defect candidates failed PP-001 and PP-002 but passed PP-003.
- The candidate that excludes prices equal to the maximum passed PP-001 and PP-002 but failed PP-003, passing 3 of its 8 tests.
- The results show that the tasks distinguish the tested price-filtering defect from the discount and rounding defects.

These observations describe the configured candidates and this run. They do not establish comparative AI-model performance.

## 6. Limitations

- The experiment uses six hand-written candidates, not a representative sample of AI-generated patches.
- The candidates were designed around defects addressed by the benchmark contracts.
- PP-001 and PP-002 overlap in functionality and should not be treated as independent measures of general software engineering ability.
- Identical results across repeated runs on one machine do not establish cross-platform reproducibility.
- Passing these tests does not prove that an implementation is free of defects beyond the tested contract.

## 7. Next evaluation work

The next phase should evaluate actual AI-generated patches. Use consistent task prompts, task versions, test environments, and scoring rules. Preserve each prompt, model and version, generated patch, test command, exit code, and result report. Include multiple attempts where feasible and report per-task outcomes rather than relying only on an aggregate score.

Any model comparison should distinguish measured observations from hypotheses and should report the number of tasks and attempts evaluated.

## 8. Current conclusion

The controlled experiment provides initial evidence that PatchProof accepts the configured reference implementation and detects the selected defect patterns. Further validation with independently generated patches and multiple AI models is required before drawing conclusions about AI-model performance.
